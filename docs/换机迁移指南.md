# 换机迁移指南

把本项目搬到另一台电脑时，**代码可用 Git 拉取**，但数据库数据、环境变量、对象存储文件不会随仓库带走。按下面步骤操作即可完整迁移。

## 项目依赖一览

| 类型          | 说明                    | 当前本机约定                          |
| ------------- | ----------------------- | ------------------------------------- |
| 业务数据库    | PostgreSQL + Prisma     | 库名 `english`（`DATABASE_URL`）      |
| AI 会话检查点 | PostgreSQL（LangGraph） | 库名 `langchain`（`AI_DATABASE_URL`） |
| 对象存储      | MinIO                   | 桶名 `avatar`（头像等）               |
| 环境变量      | `apps/backend/.env`     | **已被 gitignore，必须手动拷贝**      |

---

## 一、旧电脑：备份

### 1. 导出 PostgreSQL 数据

确认本机 PostgreSQL 服务已启动（例如 Windows 服务 `postgresql-x64-17`）。

在 PowerShell 中执行（若 `pg_dump` 不在 PATH，请改用安装目录下的完整路径，如 `C:\Program Files\PostgreSQL\17\bin\pg_dump.exe`）：

```powershell
# 业务库
pg_dump -U postgres -d english -F c -f english_main.dump

# AI / LangGraph 检查点库
pg_dump -U postgres -d langchain -F c -f english_ai.dump
```

按提示输入数据库密码（与 `.env` 中连接串一致）。

### 2. 拷贝环境变量

复制整个文件：

```text
apps/backend/.env
```

到 U 盘 / 网盘 / 加密压缩包。**不要把含真实密钥的 `.env` 提交到 Git。**

### 3.（可选）备份 MinIO

若新电脑仍需已有头像等文件，请备份 MinIO 中桶 `avatar` 的数据，或记下旧 MinIO 地址，换机后继续指向同一实例。

### 4. 带走这些文件

- 仓库代码：推送到远程后，新机 `git clone` / `git pull` 即可
- `english_main.dump`
- `english_ai.dump`
- `apps/backend/.env`
- MinIO 数据（如需要）

## 二、新电脑：安装基础环境

1. 安装 **Git**、**Node.js**（建议 LTS）、**pnpm**
2. 安装 **PostgreSQL**（建议与旧机大版本接近，例如 17）
3. 按需安装 / 启动 **MinIO**（若本机跑对象存储）
4. 克隆仓库：

```powershell
git clone <你的仓库地址>
cd english
```

5. 将旧电脑的 `.env` 放到：

```text
apps/backend/.env
```

6. 按新机器情况修改连接信息（主机、端口、密码）。库名建议仍保持：

- `DATABASE_URL` → 库 `english`
- `AI_DATABASE_URL` → 库 `langchain`

示例（密码请改成新机实际值）：

```env
DATABASE_URL="postgresql://postgres:你的密码@localhost:5432/english"
AI_DATABASE_URL="postgresql://postgres:你的密码@localhost:5432/langchain"
```

若 MinIO 地址变了，同步改 `MINIO_ENDPOINT`、`MINIO_PORT` 等。

## 三、新电脑：创建空库并导入数据

### 1. 创建空数据库

用 `psql` 或 pgAdmin 执行：

```sql
CREATE DATABASE english;
CREATE DATABASE langchain;
```

### 2. 推荐顺序：先恢复 dump，再对齐 Prisma migration

```powershell
# 导入业务数据（含表结构与数据）
pg_restore -U postgres -d english --clean --if-exists english_main.dump

# 导入 AI 检查点数据
pg_restore -U postgres -d langchain --clean --if-exists english_ai.dump
```

然后进入后端目录，用 Prisma 确认迁移历史一致：

```powershell
cd apps/backend
pnpm exec prisma migrate deploy
```

> 说明：`migrate deploy` 主要保证 schema / `_prisma_migrations` 与仓库一致。若 dump 已含完整结构和数据，它通常只会标记已应用的迁移，不会清空业务数据。

### 3. 备选顺序：先 migrate，再 restore

若你希望表结构完全由仓库里的 migration 生成：

```powershell
cd apps/backend
pnpm exec prisma migrate deploy

# 再导入数据（注意：可能与已有空表冲突，按报错调整参数）
pg_restore -U postgres -d english --data-only --disable-triggers english_main.dump
```

日常换机更推荐 **「先 pg_restore，再 migrate deploy」**。

## 四、新电脑：安装依赖并启动

在仓库根目录：

```powershell
pnpm install
```

按项目现有脚本启动（本仓库约定项目常开，开发时一般不用额外 `pnpm dev`；需要时可用 monorepo 脚本）：

```powershell
# 示例：按需启动前端 / 后端 / AI
pnpm run frontend
pnpm run backend
pnpm run ai
# 或一并启动
pnpm run all
```

启动后检查：

- 能否登录、读写业务数据（`english` 库）
- 聊天历史 / 检查点是否正常（`langchain` 库）
- 头像等资源能否访问（MinIO）

## 六、常见问题

### `pg_dump` / `pg_restore` 找不到命令

使用 PostgreSQL 安装目录下的可执行文件，例如：

```text
C:\Program Files\PostgreSQL\17\bin\pg_dump.exe
C:\Program Files\PostgreSQL\17\bin\pg_restore.exe
C:\Program Files\PostgreSQL\17\bin\psql.exe
```

或把该 `bin` 目录加入系统 PATH。

### 只想要空项目、不要旧数据

新机只需：

1. 拷贝并配置 `.env`
2. 创建空库 `english`、`langchain`
3. `pnpm install`
4. `cd apps/backend && pnpm exec prisma migrate deploy`

无需 dump / restore。AI 检查点表也可在首次启动 AI 服务时由 `PostgresSaver.setup()` 创建。

### 两边共用同一台远程数据库

把 `DATABASE_URL` / `AI_DATABASE_URL` 都指向同一云库或内网库后，换电脑只需克隆代码并拷贝 `.env`，不必再做 dump。

### 密码或密钥不要写进文档仓库

本文只写步骤和库名。真实密码、API Key、MinIO 密钥只放在本机 `.env` 中。
